Наша программа это транслятор javascript в common lisp где реализация программы на common lisp

Я планирую ограничится до функций включительно но задача должна рассматриватся как полный javascript транслятор

Какие функции должна выполнять наша программа? Она должна работать как библиотека(API), CLI утилита (запуск компиляции прямо из терминала или через скрипт SBCL), интерактивный REPL(где можно передавать код на лету и сразу проверять генерацию AST без создания файлов).

Концептуальная модель программы

Все узлы наследуются от скажем простого node. Все унаследованные узлы обладают четким приоритетом. 

Важно соблюдать правильную иерархию для построения дерева и метода рекурсивного спуска

Чтобы думать было проще мы возьмем конкретный пример выражение (const a = 10)
В примере у нас имеется узел который отвечает за корень программы, объявление переменной (const), атом (a), узел присвоения (=), литерал (10).

Таблица приоритетов (уровни 1–10). Чем ниже уровень в дереве выражения — тем раньше он выполняется.

| Ур. | Категория | Конструкции и операторы |
|-----|-----------|-------------------------|
| 1 | Корень программы | Контейнер всех инструкций файла |
| 2 | Инструкции и блоки | let, const, if, while, for, function, return, стейтменты |
| 3 | Присваивание | =, +=, -= (внутри выражений) |
| 4 | Логика | &&, \|\| |
| 5 | Сравнения | ==, !=, ===, !==, <, >, <=, >= |
| 6 | Сложение и вычитание | +, - |
| 7 | Умножение и деление | *, /, % |
| 8 | Унарные операции | !, унарный - (инкременты ++/-- отложены) |
| 9 | Вызовы функций | Передача аргументов, круглые скобки () |
| 10 | Атомы и литералы | Имена переменных, числа, строки, группирующие скобки |

Примерные модули и их ответственность (распишу подробно для более понятной структуры)
      модуль типов - должен описывать точную структуру что существует в системе. (возможно) состоит из двух блоков А и Б. блок А отвечает за типы узлов и описывает их приоритет. в блоке Б будут описаны конструкции js и их эквивалент в cl. 

      модуль лексера - его задача превратить исходный код в СПИСОК токенов. что он делает он посимвольно читает код как строку пропускает ненужную информацию типа пробелов. распознает ключевые слова которые описаны в модуле типов.

      модуль парсера - создает AST из списка токенов. рекурсивный спуск по уровням приоритета его задача собрать каркас 

      модуль семантики - на вход получает сырое AST. его задача проверять правила языка и запоминать какие переменные существуют в конкретном блоке. например const a = 10; a = 20; синтаксически верно но семантика JS это запрещает.

      модуль трансформации - на вход получает проверенное AST на выходе даёт упрощенное. это нужно для для упрощения. вместо усложенения модуля генерации кода, этот модуль находит сложный узел который дробит на более простые узлы функции и структуры.

      модуль генерации кода - преобразует AST дерево в эквивалентный на CL

      модуль тестов - должен проверять каждую функцию на корректное выполенеие.

      главный модуль - сшивает результаты работы предыдущих модулей по принципу конвеера.
