# js-to-lisp-translator

Транслятор **небольшого подмножества JavaScript** в **Common Lisp**.  
Работает в **SBCL**, без сторонних библиотек — все этапы написаны вручную на чистом Lisp.

```text
Текст JavaScript  →  токены  →  дерево  →  проверка  →  формы Lisp  →  файл / результат
```

---

# Часть 1. Как пользоваться

## Что нужно установить

| Что | Зачем |
|-----|-------|
| **SBCL** | среда Common Lisp, в которой выполняется перевод и код |
| Файлы проекта | все `.lisp` в одной папке |

Скачать SBCL: https://www.sbcl.org/

Проверка:

```powershell
sbcl --version
```

---

## Файлы, с которыми вы работаете

| Файл | Для чего |
|------|----------|
| `test.js` | ваш JavaScript — правите его |
| `test.lisp` | результат перевода (создаётся автоматически) |
| `main.lisp` | демо: дерево + генератор + запись `test.lisp` |
| `tests.lisp` | 257 автотестов |

Остальные `.lisp` — **ядро транслятора** (обычно не трогаете).

---

## Типичный рабочий цикл

1. Отредактировать `test.js`
2. Запустить перевод и выполнение
3. Посмотреть числа в терминале

### Вариант A — перевод + результат (рекомендуется)

```powershell
sbcl --load main.lisp --load test.lisp --quit
```

**Что происходит:**

| Шаг | Файл | Действие |
|-----|------|----------|
| 1 | `main.lisp` | загружает модули, читает `test.js`, печатает дерево и генератор, **перезаписывает** `test.lisp` |
| 2 | `test.lisp` | выполняется; верхние вызовы печатают результат через `(format t "~s~%" ...)` |

**Вывод:** сначала много текста (дерево AST, сгенерированный код), в **конце** — результат программы (например `120`).

### Вариант B — только результат (без дерева)

Сначала один раз пересобрать `test.lisp`:

```powershell
sbcl --load main.lisp --quit
```

Потом выполнить только переведённый файл (модули уже в памяти не останутся — нужна загрузка окружения). Проще снова использовать вариант A или REPL (ниже).

### Вариант C — автотесты

```powershell
sbcl --load tests.lisp --quit
```

В конце должно быть:

```text
==== ИТОГ ====
OK: 257 tests
```

## REPL — интерактивный режим SBCL

Запустите `sbcl`, затем:

```lisp
(load "types.lisp")
(load "lexer.lisp")
(load "parser.lisp")
(load "semantics.lisp")
(load "transformer.lisp")
(load "generator.lisp")
(load "api.lisp")

(in-package :js-to-lisp)
```

### Выполнить JS без файла

```lisp
(js-run "function sq(n) { return n * n } sq(5)")
;; => 25
```

### Перевести файл

```lisp
(js-translate-file "test.js")
;; => путь к test.lisp
```

### Выполнить `.js` напрямую

```lisp
(js-load-file "test.js")
```

### Посмотреть отдельные этапы

```lisp
(js-lex "let a = 1")
(js-parse "let a = 1")
(js-check "let a = 1")
(js-transform "let a = 1")
(js-generate "let a = 1")
```

## Правила написания JS в этом проекте

Транслятор понимает **не весь JavaScript**. Частые ошибки:

| Вы написали | Нужно |
|-------------|-------|
| `i++` | `i = i + 1` |
| `for (...; ...; i++)` | `for (...; ...; i = i + 1)` |
| тело `for` без `{ }` | тело **только** в блоке `{ ... }` |
| `a + b` отдельной строкой | присваивание, `return` или вызов функции |
| имя `gcd`, `list`, `rest` | другое имя — занято в Common Lisp |
| выражение на верхнем уровне: `a + b` | только объявления `function` и **вызовы** `foo()` |

### Пример рабочего `test.js`

```javascript
function factorial(n) {
  let result = 1
  for (let i = 1; i <= n; i = i + 1) {
    result = result * i
  }
  return result
}

factorial(5)
```

Ожидаемый результат при запуске: **120**.

# Часть 2. Как устроена программа

## Общая идея — конвейер

Программа не переводит всё сразу. Каждый модуль делает **одну** задачу и передаёт результат дальше.

```text
  JS-строка
      ↓
  [1] lexer.lisp       →  список token
      ↓
  [2] parser.lisp      →  дерево AST
      ↓
  [3] semantics.lisp   →  проверенное дерево
      ↓
  [4] transformer.lisp →  список форм Common Lisp
      ↓
  [5] generator.lisp   →  текст файла .lisp
      ↓
  [6] api.lisp         →  js-run / js-translate-file (выполнение)
```

Ошибка на любом шаге **останавливает** перевод с сообщением.

---

## Модули проекта

| Файл | Роль |
|------|------|
| `types.lisp` | типы данных: token, node, ключевые слова, операторы, приоритеты |
| `lexer.lisp` | разбор текста на token |
| `parser.lisp` | сборка token в дерево AST |
| `semantics.lisp` | проверка правил языка (области, const, return) |
| `transformer.lisp` | дерево → формы Common Lisp |
| `generator.lisp` | формы → текст `.lisp` |
| `api.lisp` | единый интерфейс: `js-lex`, `js-run`, `js-translate-file`, … |
| `main.lisp` | демо для `test.js` |
| `tests.lisp` | автотесты всех этапов |

**Порядок загрузки важен:** `types` → `lexer` → `parser` → `semantics` → `transformer` → `generator` → `api`.

---

## Этап 1 — Лексер (`lexer.lisp`)

Читает JS как строку символов и режет на **token** — смысловые кусочки.

Пример:

```javascript
let a = 1
```

```text
KEYWORD "let"
IDENTIFIER "a"
OPERATOR "="
NUMBER 1
```

### Умеет

- пробелы и переводы строк — пропускает
- ключевые слова: `let`, `const`, `if`, `function`, `for`, …
- имена, числа (целые, `10.5`, `.5`), строки `"..."` / `'...'`
- операторы: `+`, `-`, `*`, `/`, `%`, `===`, `&&`, …
- скобки, запятые, `{`, `}`
- комментарии `//`

### Минус отдельно

`-10` — это **два** token: `-` и `10`.  
Унарный минус обрабатывает **парсер**.

### Не умеет

- `/* ... */`
- шаблонные строки `` `...` ``

---

## Этап 2 — Парсер (`parser.lisp`)

Из token строит **дерево AST** (Abstract Syntax Tree).

### Узел дерева (`types.lisp`)

| Поле | Смысл |
|------|--------|
| `construct` | вид узла: `program`, `let-decl`, `binary-add`, `call`, … |
| `priority` | уровень 1–10 (приоритет в выражениях) |
| `value` | имя, оператор, литерал |
| `children` | вложенные узлы |

### Приоритеты (кратко)

| Уровень | Что |
|---------|-----|
| 10 | литералы, имена, `( ... )` |
| 9 | вызовы `foo()` |
| 8 | унарные `-`, `!` |
| 7 | `*`, `/`, `%` |
| 6 | `+`, `-` |
| 5 | сравнения |
| 4 | `&&`, `\|\|` |
| 2 | инструкции: `let`, `if`, `while`, `for`, `function` |
| 1 | корень `program` |

### Инструкции (фаза 1)

- `let`, `const`, присваивание
- `if` / `else`, `while`, `for` (ограниченная форма)
- `function`, `return`, блок `{ }`
- вызов `foo()` как отдельная инструкция

### Не умеет

- `++`, `--`
- `break`, `continue`
- массивы, объекты, классы
- выражение как самостоятельная инструкция (`a + b;`)

### Цикл `for`

Только так:

```javascript
for (let i = 0; i < n; i = i + 1) { ... }
```

Шаг — **строго присваивание** `i = i + 1`, не `i++`.  
Тело — **обязательно** `{ ... }`.

---

## Этап 3 — Семантика (`semantics.lisp`)

Проверяет **правила языка**, даже если синтаксис верный.

| Правило | Пример ошибки |
|---------|----------------|
| переменная объявлена до использования | `x = 1` без `let x` |
| `const` нельзя менять | `const a = 1` затем `a = 2` |
| `return` только внутри `function` | `return 1` снаружи функции |
| области видимости `{ }` | `let` внутри `if` не виден снаружи |
| дубликаты параметров | `function f(a, a)` |

---

## Этап 4 — Трансформер (`transformer.lisp`)

Дерево → **список форм** Common Lisp.

| JavaScript | Common Lisp |
|------------|-------------|
| `let a = 1` (верхний уровень) | `(defparameter a 1)` |
| `let a = 1` (в блоке) | `(let ((a 1)) ...)` |
| `a = a + 1` | `(setf a (+ a 1))` |
| `while (i <= n) { ... }` | `(loop while (<= i n) do ...)` |
| `for (...)` | `(loop while ... do ... setf ...)` |
| `function f(a) { return x }` | `(defun f (a) (return-from f x))` |
| `a === b` | `(equal a b)` |
| `a && b` | `(and a b)` |

### Порядок форм программы

1. все `defun` (функции)
2. остальные инструкции **в порядке исходника**

### Имена

Имена JS → символы Lisp в пакете `:js-to-lisp`.  
Если имя совпало с встроенным Common Lisp (`list`, `gcd`, `rest`, …) — **ошибка трансформера**.

### Вывод в файл

Для `js-generate` / `js-translate-file` верхние **вызовы** (не объявления) оборачиваются в:

```lisp
(format t "~s~%" ...)
```

Поэтому `(load "test.lisp")` **печатает** результат.  
Для `js-run` обёртки **нет** — возвращается последнее значение.

---

## Этап 5 — Генератор (`generator.lisp`)

Список форм → **текст файла**.

Шапка каждого сгенерированного файла:

```lisp
;;;; Сгенерировано транслятором js-to-lisp
(in-package :js-to-lisp)
```

Между формами — пустая строка. Имена — в нижнем регистре.

---

## API (`api.lisp`)

Пакет `:js-to-lisp`.

| Функция | Вход | Выход |
|---------|------|-------|
| `js-lex` | строка JS | список token |
| `js-parse` | строка или token | дерево |
| `js-check` | строка или дерево | проверенное дерево |
| `js-transform` | строка или дерево | формы Lisp |
| `js-generate` | строка или формы | текст `.lisp` |
| `js-run` | строка или формы | выполняет, **последнее значение** |
| `js-translate-file` | путь `.js` | пишет `.lisp` рядом |
| `js-load-file` | путь `.js` | читает и выполняет |
| `js` | строка (макрос) | вставляет формы в ваш код на этапе компиляции |

## Полный пример — от JS до результата

### Исходник

```javascript
function max2(a, b) {
  if (a > b) {
    return a
  } else {
    return b
  }
}
max2(10, 3)
```

### После перевода (смысл)

```lisp
(defun max2 (a b)
  (if (> a b)
      (return-from max2 a)
      (return-from max2 b)))

(format t "~s~%" (max2 10 3))
```

### Результат в терминале

```text
10
```

## Что поддерживается (фаза 1)

| Категория | Поддержка |
|-----------|-----------|
| `let`, `const` | да |
| числа, строки, `true`/`false` | да |
| арифметика, сравнения, логика | да |
| `if`/`else`, `while`, `for` | да |
| `function`, `return`, вызовы | да |
| комментарии `//` | да |
| `++`/`--` | **нет** |
| `/* */` | **нет** |
| массивы, объекты, классы | **нет** |
| ASI (авто-`;`) | **нет** |

---

## Отличия от полного JavaScript

| Тема | JavaScript | Наш перевод |
|------|------------|-------------|
| `==` / `===` | разные правила | оба → `equal` |
| «ложные» значения | `0`, `""` — false | в Lisp false только `nil` |
| `&&`, `\|\|` | с ложностью JS | обычные `and` / `or` |
| регистр имён | `foo` ≠ `Foo` | всё → нижний регистр |
| `+` для строк | склеивает | `+` только для чисел |

## Частые сообщения об ошибках

| Сообщение | Причина |
|-----------|---------|
| `Parser: ... ожидался OPERATOR "="` | часто `i++` вместо `i = i + 1` |
| `Parser: неизвестная инструкция` | выражение на верхнем уровне или тело `for` без `{ }` |
| `Semantics: const "a" нельзя изменять` | переприсвоение `const` |
| `Transformer: имя "..." зарезервировано` | имя занято в Common Lisp |
| `OK: 257 tests` | всё в порядке |
