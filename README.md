Наша программа это транслятор javascript в common lisp где реализация программы на common lisp

Я планирую ограничится до функций включительно но задача должна рассматриватся как полный javascript транслятор

# Какие функции должна выполнять наша программа?

- Она должна работать как библиотека (API)
- CLI утилита (запуск компиляции прямо из терминала или через скрипт SBCL)
- интерактивный REPL (где можно передавать код на лету и сразу проверять генерацию AST без создания файлов)

## Концептуальная модель программы

Все узлы наследуются от скажем простого node. Все унаследованные узлы обладают четким приоритетом.
Важно соблюдать правильную иерархию для построения дерева и метода рекурсивного спуска

Чтобы думать было проще мы возьмем конкретный пример выражение:
`const a = 10`

В примере у нас имеется узел который отвечает за корень программы, объявление переменной (`const`), атом (`a`), узел присвоения (`=`), литерал (`10`).

это должно быть как то так:

- КОРЕНЬ ПРОГРАММЫ
  - ОБЪЯВЛЕНИЕ ПЕРЕМЕННОЙ
    - АТОМ
    - ЛИТЕРАЛ

Рассмотрим другой пример `a = 10`

- КОРЕНЬ ПРОГРАММЫ
  - ПРИСВОЕНИЕ ЗНАЧЕНИЯ
    - АТОМ
    - ЛИТЕРАЛ

### Таблица приоритетов

Таблица приоритетов (уровни 1–10). Чем ниже уровень в дереве выражения — тем раньше он выполняется.

| Ур. | Категория | Конструкции и операторы |
|-----|-----------|-------------------------|
| 1 | Корень программы | Контейнер всех инструкций файла |
| 2 | Инструкции и блоки | let, const, if, while, for, function, return, стейтменты |
| 3 | Присваивание | =, +=, -= (внутри выражений) |
| 4 | Логика | &&, \|\| |
| 5 | Сравнения | ==, !=, ===, !==, `<, >, <=, >=` |
| 6 | Сложение и вычитание | +, - |
| 7 | Умножение и деление | *, /, % |
| 8 | Унарные операции | !, унарный - (инкременты ++/-- отложены) |
| 9 | Вызовы функций | Передача аргументов, круглые скобки () |
| 10 | Атомы и литералы | Имена переменных, числа, строки, группирующие скобки |

## Примерные модули и их ответственность

- **модуль типов** — описывает точную структуру что существует в системе. (возможно) состоит из двух блоков А и Б. блок А отвечает за типы узлов и описывает их приоритет. в блоке Б будут описаны конструкции js и их эквивалент в cl.
- **модуль лексера** — превращает исходный код в СПИСОК токенов. посимвольно читает код как строку, пропускает пробелы, распознает ключевые слова из модуля типов.
- **модуль парсера** — создает AST из списка токенов. рекурсивный спуск по уровням приоритета, собирает каркас.
- **модуль семантики** — проверяет правила языка и запоминает переменные в блоке. например `const a = 10; a = 20;` — синтаксически верно, но семантика JS запрещает.
- **модуль трансформации** — упрощает проверенное AST перед генерацией. дробит сложные узлы на простые.
- **модуль генерации кода** — преобразует AST в эквивалент на CL.
- **модуль тестов** — проверяет каждую функцию на корректное выполнение.
- **главный модуль** — сшивает модули по принципу конвейера.
